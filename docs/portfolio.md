# Portfolio

One responsive profile page for **Mahadi Sajjad Neloy**, built with
[SvelteKit](https://kit.svelte.dev). Cloudflare, Vercel, and Netlify use static
builds; Render runs the same app with SvelteKit's Node server adapter.

## Develop

Requires Node.js 22.17 or newer and npm.

```sh
npm ci
npm run dev
```

Run the Svelte and TypeScript checks with:

```sh
npm run check
```

## Build and deploy

Run the provider-specific build command:

| Setting | Cloudflare Workers | Vercel | Netlify | Render |
| --- | --- | --- | --- | --- |
| Framework preset | SvelteKit | SvelteKit | SvelteKit | Node |
| Install command | `npm ci` | Configured by `vercel.json` | `npm install` | `npm ci` |
| Build command | `npm run build:cloudflare` | Configured by `vercel.json` | Configured by `netlify.toml` | `npm run build:render` |
| Runtime command | `npx wrangler deploy` | Managed by Vercel | Managed by Netlify | `npm start` |
| Adapter | `adapter-cloudflare` | `adapter-vercel` | `adapter-netlify` | `adapter-node` |

For **Cloudflare Workers**, import the repository in Workers Builds and use
`npm ci` as the install command, `npm run build:cloudflare` as the build
command, and `npx wrangler deploy` as the deploy command. `wrangler.toml`
points to the Worker and static assets generated by `adapter-cloudflare`.

For **Vercel**, import the repository and select the SvelteKit framework
preset. `vercel.json` uses `adapter-vercel`'s build output and configures
security and cache headers.

For **Netlify**, import the repository and let `netlify.toml` select
`adapter-netlify`, its `build` publish directory, Node.js version, and
security/cache headers.

For **Render**, create a Blueprint from the repository using `render.yaml`.
It defines a Node.js web service that builds with SvelteKit's Node adapter and
starts the generated server with `npm start`. Alternatively, choose
**New > Web Service** in the Render dashboard, use the Node runtime, set the
build command to `npm ci && npm run build:render`, and set the start command
to `npm start`.

All four hosts now render pages dynamically with server-side rendering, using
the platform adapter selected by each build script. `npm run build` remains an
alias for the Render Node build. Cloudflare Workers runs on its Workers
runtime; use Web APIs and Cloudflare bindings rather than assuming Node.js APIs
are available.

The page metadata and Person structured data are rendered per request on each
host.
The canonical URL and sitemap currently target `https://neloy.vercel.app/`;
update `siteUrl` in `src/lib/profile.ts`, `static/sitemap.xml`, and
`static/robots.txt` together if the primary domain changes. After deployment,
verify `https://neloy.vercel.app/` as a URL-prefix property in Google Search
Console, inspect the homepage, request indexing, and submit
`https://neloy.vercel.app/sitemap.xml`. Search Console verification and
indexing requests must be completed by the site owner, and indexing is not
instant or guaranteed.

The WakaTime dashboard fetches the same public share JSON feeds as the README
charts directly in the browser on page load, with manual refresh and a
15-minute refresh interval. No WakaTime secret or GitHub Actions-generated
site data is required.
